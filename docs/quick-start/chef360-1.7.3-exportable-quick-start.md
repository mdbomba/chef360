# Chef 360 Platform 1.7.3 Exportable Quick-Start Guide

## Single-Node Hyperconverged Non-HA Deployment

**Target release:** Chef 360 Platform 1.7.3

**Audience:** Linux administrators, evaluators, existing Chef customers, Solutions Engineers, and Professional Services consultants

**Outcome:** Install Chef 360 Platform, configure an initial tenant and organizational unit, retrieve the tenant administrator one-time password from Mailpit, set a permanent password, and sign in to the Apps Console at `https://<FQDN>:31000`.

This is a self-contained export derived from the canonical project guide. Confirm release-specific requirements and download information with Progress before using it for another Chef 360 release.

## 1. Deployment Model

<!-- GUIDANCE-DIFFERENCE: GD-010 -->

This guide deploys all Chef 360 services on one Linux server using the integrated Replicated-based installer. The installer provisions and manages the embedded Kubernetes environment. You do not need to install Kubernetes, configure Helm, or provide an external Kubernetes cluster, load balancer, or shared storage.

This topology has no high-availability components. It is suitable for evaluations, proofs of concept, labs, training, small deployments, and initial migration testing.

For an existing single-node, non-HA Chef Infra customer retaining the same availability model, this is the closest Chef 360 architectural match. It is not a hardware-sizing equivalence; size Chef 360 independently for its expected workload.

The quick start ends after successful Apps Console sign-in and validation of the initial tenant and organizational unit. It does not cover Chef Workstation, Chef 360 CLI registration, managed-node enrollment, Courier jobs, Chef Automate integration, backup, upgrades, or routine operations.

## 2. Terminology and Ports

- **Admin Console:** Replicated-based installation and cluster-management interface on TCP `30000`.
- **Apps Console:** Tenant-facing Chef 360 Platform interface at `https://<FQDN>:31000`.
- **Mailpit:** Optional non-production email catcher with an HTTP web interface on TCP `31101`.

The Admin Console password and Apps Console tenant administrator credentials are separate.

Permit these initial flows:

| Source | Destination | Port | Purpose |
|---|---|---:|---|
| Approved administrators | Chef 360 host | TCP 22 | Linux administration |
| Platform administrators | Chef 360 host | TCP 30000 | Admin Console |
| Tenant administrator | Chef 360 host | TCP 31000 | Apps Console |
| Platform administrators | Chef 360 host | TCP 31101 | Mailpit HTTP UI, if enabled |
| Chef 360 host | Internet services | TCP 443 | Online installation downloads |

For an online installation, permit outbound TCP `443` to:

- `registry.chef360.chef.io`
- `download.chef360.chef.io`
- `proxy.chef360.chef.io`
- `appservice.chef360.chef.io`
- `index.docker.io`
- `cdn.auth0.com`
- Required `docker.io` and `docker.com` subdomains

## 3. Gather Required Information

Before building the server, record:

- Active Chef Compliance managed-endpoint license
- Chef 360 download authorization code and distribution URL
- Static IP address, subnet, gateway, and DNS servers
- Short hostname and FQDN
- Optional server certificate, unencrypted private key, and CA chain
- Tenant name, tenant TLD, tenant subdomain, and default organizational unit name
- Tenant administrator first name, last name, and email address
- Email choice: Mailpit for a lab or the organization's SMTP service

Never store real authorization codes, passwords, private keys, tokens, or downloaded license files in documentation or source control.

## 4. Obtain a Chef 360 Authorization Code

<!-- GUIDANCE-DIFFERENCE: GD-011 -->

Chef Compliance is the managed-endpoint entitlement. The Chef 360 authorization code is a separate download credential and is not automatically supplied with the entitlement.

1. Confirm that the customer has an active Chef Compliance managed-endpoint license.
2. Contact the assigned Progress account team or Progress Support.
3. Request Chef 360 download access based on the active Chef Compliance license.
4. Obtain the Chef 360 authorization code and distribution URL supplied by Progress.
5. Use the authorization code only to download the Chef 360 distribution package.

The downloaded online or air-gapped package contains the authorization-specific `license.yaml` used by the installer. Do not substitute a Chef Automate, Chef Workstation, Chef Infra Client, or other traditional Chef product license file.

Treat the authorization code as sensitive. Do not commit it, include it in support bundles, place it in shared documentation, or leave it in shell history.

## 5. Prepare the Linux Host

<!-- GUIDANCE-DIFFERENCE: GD-001, GD-002, GD-003, GD-004, GD-005, GD-006, GD-007 -->

Confirm the selected operating system is supported by Chef 360 Platform 1.7.3. For a new deployment, this project recommends Ubuntu Server 24.04 LTS or Rocky Linux 10 and Linux kernel 6.1 or later where possible.

### Minimum Resources

| Resource | Minimum |
|---|---:|
| vCPU | 16 |
| Memory | 32 GB |
| Total storage | 200 GB |

This project recommends separate `/boot`, `/`, and `/var/lib` filesystems. Allocate 1 GB to `/boot`, 50 to 100 GB to `/`, and at least 200 GB to `/var/lib`; 500 GB for `/var/lib` is preferred. On KVM, prefer ext4 for `/var/lib`; XFS with `ftype=1` is also allowed. Do not mount `/var` with `noexec`.

Use a static server address and a permanent RFC 1123-compliant FQDN. Register the FQDN in DNS or use consistent host-file entries in a lab.

Example:

```text
Hostname: chef360
FQDN:     chef360.lab.example.com
Address:  192.168.1.10
```

Set and verify the hostname:

```bash
sudo hostnamectl set-hostname chef360.lab.example.com
hostname -f
```

Fully update the operating system and reboot if the kernel or core components change:

```bash
# Ubuntu
sudo apt update && sudo apt upgrade -y

# Rocky Linux
sudo dnf update -y
```

For the Rocky Linux quick-start path, this project recommends disabling SELinux before installation. Contact Progress Support before using Enforcing, permanent Permissive, or custom-policy configurations.

Disable all host swap, remove or comment out persistent swap configuration in `/etc/fstab`, and check for systemd-managed swap:

```bash
sudo swapoff -a
swapon --show=NAME,TYPE,SIZE,USED,PRIO
systemctl list-units --type=swap --state=active
```

Both swap checks must show no active swap, including after reboot.

Validate resources and storage:

```bash
uname -r
timedatectl
nproc
free -h
lsblk
findmnt /var/lib
findmnt -T /var/lib -no FSTYPE,OPTIONS
findmnt -T /var -no OPTIONS
df -h / /var/lib
```

The installation account must be able to perform privileged operations without an interactive sudo password prompt. Confirm this is permitted by organizational security policy.

## 6. Plan TLS Certificates

<!-- GUIDANCE-DIFFERENCE: GD-008 -->

Custom certificates are optional but recommended. Prepare:

- Server certificate in Base64-encoded PEM format with a `.crt` extension
- Matching unencrypted private key in PEM format with a `.key` extension
- CA chain in Base64-encoded PEM format with a `.crt` extension

When PKI policy permits, include the FQDN, short hostname, and server IP address as Subject Alternative Names. Protect the private key according to organizational policy.

## 7. Download and Install Chef 360

The script below is the complete maintained project helper. Online mode downloads, extracts, validates, and starts installation. Air-gap mode downloads and validates the air-gapped package, then stops so the artifacts and required Velero plugin images can be transferred to the disconnected Chef 360 host.

The authorization-code prompt does not display the value. The script passes the authorization header to `curl` through standard input so it is not present in the `curl` process arguments.

<!-- BEGIN EMBEDDED SCRIPT: scripts/chef360/download-install-server.sh -->
```bash
#!/bin/bash

set -euo pipefail

VERSION="1.7.3"
BASE_URL="https://appservice.chef360.chef.io/embedded/chef-360/stable/${VERSION}"

read -r -p "Download the air-gapped package? [y/N]: " AIRGAP
case "$AIRGAP" in
    [Yy])
        DOWNLOAD_URL="${BASE_URL}?airgap=true"
        ARCHIVE="chef-360-${VERSION}-airgap.tgz"
        AIRGAP=true
        ;;
    *)
        DOWNLOAD_URL="$BASE_URL"
        ARCHIVE="chef-360-${VERSION}.tgz"
        AIRGAP=false
        ;;
esac

read -r -s -p "Enter your Chef 360 authorization code: " AUTH
printf '\n'
trap 'unset AUTH' EXIT

# Read the header from stdin so the authorization code is not in curl's arguments.
printf 'Authorization: %s\n' "$AUTH" |
    curl --fail --location --show-error --header @- "$DOWNLOAD_URL" -o "$ARCHIVE"
unset AUTH
trap - EXIT

tar -xzf "$ARCHIVE"
test -f chef-360
test -s license.yaml

if [[ "$AIRGAP" == true ]]; then
    test -s chef-360.airgap
    printf '%s\n' \
        "Air-gapped package ready." \
        "Transfer chef-360, chef-360.airgap, and license.yaml to the Chef 360 host." \
        "Also transfer and preload the release-specific Velero plugin images before installation." \
        "Then run: sudo ./chef-360 install --license license.yaml --airgap-bundle chef-360.airgap"
    exit 0
fi

sudo ./chef-360 install --license license.yaml
```
<!-- END EMBEDDED SCRIPT -->

For an online installation, put the text in a shell file on the Chef 360 host, make it executable, and run it:

```bash
chmod 700 download-install-server.sh
./download-install-server.sh
```

Answer `N` or press Enter for the online package, then enter the authorization code when prompted. Do not proceed if `chef-360` or a non-empty `license.yaml` is missing after extraction.

During installation:

1. Resolve preflight failures instead of bypassing them.
2. Create and confirm the Admin Console password when prompted.
3. Store the password in the organization's approved credential manager.
4. Record the complete `Admin Console accessible at:` link returned by the installer.

### Complete the Air-Gapped Prerequisites

Answer `Y` only when staging an air-gapped package. In addition to the Chef 360 air-gap bundle, Chef 360 Platform 1.7.3 requires these two Velero plugin container images:

| Image | Purpose |
|---|---|
| `docker.io/progressofficial/chef360:1.0.3` | PostgreSQL backup and restore plugin for Velero |
| `docker.io/velero/velero-plugin-for-aws:v1.12.1` | AWS S3 storage plugin for Velero |

An air-gapped embedded Kubernetes cluster cannot pull these images from the Internet. If they are not preloaded before installation, Velero fails to start because it cannot pull its initialization container images.

#### 1. Pull and Save the Images on the Jump Host

On the Internet-connected jump host with Docker installed, run:

```bash
sudo docker pull --platform linux/amd64 \
  docker.io/progressofficial/chef360:1.0.3
sudo docker save docker.io/progressofficial/chef360:1.0.3 \
  -o velero-plugin-cnpg-restore.tar

sudo docker pull --platform linux/amd64 \
  docker.io/velero/velero-plugin-for-aws:v1.12.1
sudo docker save docker.io/velero/velero-plugin-for-aws:v1.12.1 \
  -o velero-plugin-for-aws.tar
```

Verify both archives:

```bash
ls -lh velero-plugin-cnpg-restore.tar velero-plugin-for-aws.tar
```

#### 2. Transfer All Installation Files

Transfer the installer, air-gap bundle, authorization-specific license, and both plugin archives through the organization's approved process. For example:

```bash
scp chef-360 chef-360.airgap license.yaml \
  velero-plugin-cnpg-restore.tar velero-plugin-for-aws.tar \
  admin@chef360.lab.example.com:
```

The `scp` command is only an example. Use USB, approved removable media, a controlled file-transfer gateway, or another authorized method when direct network transfer is not allowed.

#### 3. Preload the Images on the Air-Gapped Host

On the disconnected Chef 360 host, copy both image archives into the embedded k0s image store before running the Chef 360 installer:

```bash
sudo mkdir -p /var/lib/embedded-cluster/k0s/images/
sudo cp velero-plugin-cnpg-restore.tar \
  /var/lib/embedded-cluster/k0s/images/
sudo cp velero-plugin-for-aws.tar \
  /var/lib/embedded-cluster/k0s/images/
```

Verify that both files are present and non-empty:

```bash
sudo ls -lh /var/lib/embedded-cluster/k0s/images/
sudo test -s \
  /var/lib/embedded-cluster/k0s/images/velero-plugin-cnpg-restore.tar
sudo test -s \
  /var/lib/embedded-cluster/k0s/images/velero-plugin-for-aws.tar
```

#### 4. Install Chef 360 Platform

From the directory containing `chef-360`, `chef-360.airgap`, and `license.yaml`, run:

```bash
sudo ./chef-360 install \
  --license license.yaml \
  --airgap-bundle chef-360.airgap
```

## 8. Open the Admin Console

Use the complete link returned by the installer. It uses TCP `30000` and may contain a required path or query string:

```text
https://<INSTALLER-RETURNED-HOST>:30000
```

If the returned host is inaccessible from the administrator workstation, replace only the host with the public FQDN. Preserve the returned scheme, port, path, and query string. Sign in with the Admin Console password created during installation.

Install the custom certificate, private key, and CA chain if they are being used.

## 9. Create the Initial Configuration

In the Admin Console:

1. Select **Advanced Configuration**.
2. Review and accept the terms and conditions.
3. Configure the default tenant.
4. Configure the default organizational unit.
5. Configure the initial tenant administrator.
6. Select Mailpit for a demonstration, evaluation, training, or lab deployment.
7. Review preflight results and apply the configuration.

Example tenant values:

```text
Tenant name:      Lab
Tenant TLD:       lab.example.com
Tenant subdomain: chef360
Generated FQDN:   chef360.lab.example.com
```

Tenant names cannot contain underscores. Ensure the generated tenant FQDN matches DNS and the certificate SANs.

Enter a unique, friendly default organizational unit name and optional description. Then enter the initial tenant administrator's first name, last name, and email address. Chef 360 sends the account-registration one-time password to that address through the configured email service.

## 10. Use Mailpit to Complete Account Registration

Mailpit is intended only for non-production use. Its default web UI is HTTP on TCP `31101`:

```text
http://<CHEF360-IP>:31101
```

The Admin Console may display the Mailpit link with `https://`. Chef 360 does not support HTTPS for Mailpit. Change only the scheme to `http://` and retain the displayed host and port.

After the initial configuration is applied:

1. Open `http://<CHEF360-IP>:31101` from an approved administrator workstation.
2. Locate the message addressed to the tenant administrator.
3. Retrieve the one-time password from the message.
4. Open the Apps Console at `https://<FQDN>:31000`.
5. Sign in with the tenant administrator email address and one-time password.
6. Set the permanent tenant administrator password when prompted.
7. Confirm that the expected tenant and default organizational unit are visible.

Do not use the Admin Console password to sign in to the Apps Console.

## 11. Validate the Installation

From the appropriate administrator workstation, test the required ports:

```bash
nc -zv <CHEF360-IP> 30000
nc -zv <CHEF360-FQDN> 31000
nc -zv <CHEF360-IP> 31101
```

Confirm all of the following:

- The Admin Console is reachable using the installer-returned link on TCP `30000`.
- Chef 360 services report a healthy state.
- The Admin Console Dashboard reports current version `1.7.3`.
- Mailpit received the tenant administrator account-registration message.
- The tenant administrator set a permanent password.
- The Apps Console is reachable at `https://<FQDN>:31000`.
- The tenant administrator signed in successfully.
- The expected tenant and default organizational unit are visible.

## 12. Troubleshooting

If the Admin Console does not open, verify the complete installer-returned link, routing, and TCP `30000`. If the Mailpit link does not open, use HTTP rather than HTTPS and verify TCP `31101`. If the Apps Console does not open, verify tenant FQDN resolution, certificate trust, initial configuration status, service health, and TCP `31000`.

Before sharing diagnostics, remove authorization codes, passwords, private keys, tokens, and other secrets.
